# 真实工业背景驱动的应用论文

[English](../../skills/background-driven-industrial-application/SKILL.md)

套件版本：`4.2.36`

## 一、任务目标

从实际工程背景生成论文：

`工业机制 -> 运行问题 -> 可观测证据 -> 技术定义 -> 背景引导方案 -> 应用价值`

工业对象不是方法完成后添加的例子，而是问题、假设、模块和评价的来源。

## 二、适用判断

适用于：

- 一个过程、产线、设备类或运行流程是中心；
- 不理解背景就无法理解问题；
- 工艺约束或专家知识塑造方法；
- 标签来自生产、检验、维护或控制实践；
- 工程价值至少与算法通用性同等重要。

benchmark 可有可无，不能支配论文。

## 三、提取工程问题

在提出模型前记录：

1. 物理或运行目标；
2. 生产路线或设备功能；
3. 故障、质量、安全、效率或控制问题；
4. 当前如何判断或处理；
5. 可用测量及其时间；
6. 哪些约束使现有实践不足；
7. 模型输出支持什么决策。

未知事实不得补写成技术 gap。

## 四、区分创新类型

- **问题创新**：实际重要问题尚未被准确建模；
- **方法创新**：针对过程/数据条件提出机制；
- **集成创新**：新的方式连接过程知识、传感、建模和决策。

不要为了显得“通用”而削弱真实贡献。

## 五、建立背景-设计映射

| 已有依据的背景事实 | 建模问题 | 可承担的作用，不是必选方法 | 匹配主张的证据 |
|---|---|---|---|
| 运行周期 | 哪段历史或周期内变化影响输出？ | 需要时组织时间信息 | 与主张有关的周期分解结果 |
| 生产工序 | 哪些已知归属或关系影响任务？ | 实际采用的输入组织或关系建模 | 匹配所声称作用的结构对比 |
| 物理关系 | 是定律、连接还是经验指导？ | 已实现的约束或结构用法 | 相应的物理残差或工艺对应证据 |
| 延迟质量目标 | 目标和预测输入何时可用？ | 实际学习与决策时间边界 | 可用性核查及目标预测结果 |
| 工况变化 | 什么发生变化，可用什么信息？ | 本研究选定的响应，不默认适应 | 匹配主张的留出或顺序评价 |

这些是条件性示例，不是一对一的问题—方法处方。以真实事实解释关键设计；支撑操作需要明确作用，不必分别对应一个工业难题。未能解释的组件交作者讨论，不能在写作时自动删除。工况改变本身不证明某种分布漂移，也不要求在线适应。

多信息来源相关时，按实际角色建立：

`来源 -> 测量或派生视图 -> 所需对应/聚合 -> 表征 -> 已定义任务输出`

先区分采集流、不同工况的数据集和派生视图，再谈模态或同步；跨域训练数据不必共享事件时间戳。只有研究了操作员/控制动作才接入这一环节，单纯预测不必具备它。

## 六、标题、摘要与引言

当应用对象定义贡献时，标题应体现对象。摘要说明工业任务、运行/测量困难、已核实的剩余要求或研究目的、背景引导方案、关键机制、真实条件评价和有边界的工程结论。

引言建议：

1. 工业过程/设备及重要性；
2. 实际故障、质量、控制或监控问题；
3. 当前工程能力与有依据的局限；
4. 测量与数据机制；
5. 相关分析和数据驱动方法；
6. 与实际应用有关的已核实要求或范围差异；
7. 从背景推导方案；
8. 贡献与工程意义。

以上是论证功能，不是八个必需段落；按实际证据合并或调整顺序，保持具体应用主线及逻辑递进。

## 七、Related Work

平衡：过程/设备专用研究、领域中的解析/统计/数据驱动方法、中心数据条件的建模，以及知识/约束/机理引导方法。不能只引用机器学习论文。

## 八、过程与数据描述

说明：

- 物理单元、工序、路线或周期；
- 传感器、操纵变量、检验和控制动作；
- 采样与同步；
- 样本是点、窗口、批次、产品、运行、campaign 还是机器；
- 标签/目标来源和时间；
- 工况分布、缺失、噪声和不平衡；
- 实际训练、选择和测试安排及其运行含义；只有存在验证子集时才描述它。

只保留决定数据、任务、假设和评价的硬件/系统细节，避免写成设备说明书。

## 九、问题定义与方法推导

明确推理时可用信息、输出和决策时域、已知约束、未知关系及站点特定假设，防止未来检验或下游信息泄漏。

问题定义建立真实任务和信息边界，不必宣称通用模型一律不足。方法按实际学习/预测依赖组织，保留并行路径，映射表行序不强制决定前向顺序。关键或不直观设计说明背景事实、建模需求、操作、保留/约束的信息、学习内容和后续用途；普通支撑操作可简明交代。

## 十、评价设计

实验应回答：

- 是否改善真实决策？
- 是否优于当前工程或分析实践？
- 哪个过程引导模块有效？
- 在产品、负荷、配方、campaign 或时间变化下是否保持？
- 稀有重要工况如何？
- 噪声、缺失、漂移或传感器故障下如何？
- 输出是否足够及时？

不要为“看起来完整”添加无关 benchmark 实验。

## 十一、对比与结果解释

对比应兼顾工程与数据驱动审稿人：当前实践/解析方法、统计或机器学习、相关深度学习、近期专用方法和本文方法。比较时核对预测时刻实际可用输入；训练期额外资源另行声明并按主张比较，不能把特权训练信息一律判为泄漏。

通过工序、设备部件、工况、故障/质量类别、生产时期、变量组和决策价值解释结果，不把所有改进都归因于“更好的特征提取”。

可复用结果文字按[主结果写法](../../references/section-writing-guide.md#12-main-results)，综合解释按[Discussion](../../references/section-writing-guide.md#15-discussion)；内部核查要求与论文文字分开。

## 十二、工程适用性与限制

讨论传感器要求、拓扑/专家知识依赖、设备变化后的再校准、计算/时间要求、异常测量处理，以及当前回顾性、前瞻性、影子运行或在线验证范围。

有意义的限制包括单站点、有限时期、站点标签、未测试工况、传感质量、缺少在线闭环、设备或控制规则变化。说明限制如何约束结论，不列泛泛未来工作。

## 十三、质量门

- 背景直接生成研究问题；
- 关键设计对应工程要求，支撑操作有明确作用；
- 工艺和数据来源可复核；
- 划分与预测时点符合运行逻辑；
- 应用文献充分；
- 结论不超过所测过程范围；
- 工程相关性与部署分开；
- 必要图展示真实对象或工作流。
