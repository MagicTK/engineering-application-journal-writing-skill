# 工程应用文献调研与研究定位

套件版本：`4.1.38`

## 一、任务目标

把文献集合转化为可验证的工程研究定位：

`工业需求 -> 已有工程实践 -> 相关方法类别 -> 未解决的假设/能力 -> 本文研究`

输出不是论文列表，而是说明“已知什么、证据覆盖什么条件、当前任务还缺什么”的结构化图谱。

使用[工业智能多维分类](../../references/industrial-ai-taxonomy.md)按工程挑战、方法、任务、对象层级和证据作用标注文献，不能把文件夹名当作互斥科学类别。

## 二、定义检索对象

检索前明确：

- 工程对象：过程、设备、产线、产品、系统或运行环节；
- 任务：监控、检测、诊断、隔离、预测、控制、优化或决策支持；
- 实际条件：多工序、多速率、多工况、小样本、域偏移、缺失、干扰或不平衡；
- 已知方法类别；
- 目标期刊和时间范围；
- 论文范式。

检索式应组合工程对象、任务、数据条件和方法，不只搜索模型关键词。

### 保留导航与阅读证据

作者文件夹作为一级导航，科学角色另作可重叠标注；工程问题来源、候选机制来源、最近邻/重复风险分开记录，不打散原目录。文件名/身份核验、文本提取、摘要阅读、指定页阅读与全文精读分别登记。批量检索不等于逐篇审查或穷尽查新。团队稿件须核对题名、作者、期刊和版本，主题相似不能替代身份确认。详见[来源与阅读状态](../../references/research-planning-and-contribution.md)。

## 三、建立四层文献库

1. **工程基础层**：工艺、设备、控制、传感、故障机理、数据来源和运行实践。
2. **任务层**：故障诊断、过程监控、质量预测、异常定位等。
3. **方法层**：统计、机器学习、深度学习、知识引导和表征学习。
4. **评价层**：数据集、案例、指标、划分方式和近期对比方法。

背景驱动论文不能让通用 ML 文献支配前两层；通用方法论文也需要工程基础层支撑假设。

## 四、按作用标注文献

- `foundation`：工艺、任务、数据集或经典方法；
- `closest`：问题和假设最接近；
- `method`：支持技术类别；
- `contrast`：体现不同假设或局限；
- `evaluation`：支持设置、指标和案例惯例；
- `terminology`：校准术语和写作方式。

方法优先引用原始论文，工艺事实优先权威来源。

## 五、引用前验证

逐项核对标题、作者、期刊、年份、卷页/文章号、DOI、实际支持的论断和 BibTeX。不得凭记忆生成参考文献。无法确认时标记 `VERIFY`。

## 六、提取文献矩阵

| 字段 | 核心问题 |
|---|---|
| 原始位置 | 保留作者文件夹/文件或archive/member导航，有现成索引时继承。 |
| 来源作用 | 工程问题、候选机制、最近邻/重复风险；允许同一来源承担多个作用。 |
| 阅读状态 | 身份核验、提取、已读页/节、精读与未覆盖部分。 |
| 工程背景 | 研究哪个过程或系统？ |
| 任务 | 输出什么决策？ |
| 数据条件 | 困难来自哪里？ |
| 假设 | 方法需要什么前提？ |
| 设计原则 | 如何回应问题？ |
| 证据 | 用哪些案例与实验？ |
| 边界 | 没有证明什么？ |
| 术语 | 哪些领域词反复出现？ |

阅读状态核查应简明报告覆盖范围、来源位置和后续阅读重点，即使请求只是纠正夸大的精读声明。保留原文件夹/文件或压缩包/成员导航，区分工程问题、方法机制与最近竞争工作的阅读重点。没有提供位置时，说明现有索引应保留这些字段，不编造路径，也不省略这部分来源信息。比较假设与证据，不只比较网络结构。

区分已有工作的真实能力、未评估范围、不同假设与同条件实验证明的不足。别人未研究某条件，不等于证明其方法不能处理。Related Work按能力和条件的演进递进，让每组研究自然连到当前要求；新问题和既有问题两类写作均按[贡献论证路径](../../references/contribution-narratives.md)校准。

## 七、构建非稻草人的 Gap

研究空白应满足：

1. 来自真实工程或数据现象；
2. 多个代表性方法确实共享相关局限；
3. 局限会影响工程任务；
4. 本文能够设计实验验证响应方案。

优先写“已有方法在何种假设下不能处理何种信息”，避免笼统的 `ignore important information`。除非系统检索支持，不写“尚无任何工作”。

## 八、建立工程术语与模型术语桥梁

| 工程层 | 模型层 |
|---|---|
| process variable | 定义后可对应 input channel |
| production stage | stage-wise subset/branch |
| acquisition cycle | rate factor/interval encoding |
| process topology | graph/mask/constraint |
| operating condition | domain/condition label |
| inspection cue | localization map/visual evidence |

先讲工程含义，再讲计算表示。

## 九、使用多篇论文校准写作

按问题选择相近论文中的有效段落，不设最低篇数。纯语法校正无需启动文献检索；争议术语需核对相近用例与机制语境；章节重构才需要较广的匹配语料。根据当前任务提取摘要功能、引言段落作用、Related Work 分类、实验表述、结论强度或图表惯例，把它们视为观察到的惯例而非句子模板，不复制原句。

## 十、组织 Related Work

每个主题小节完成：

1. 定义方法类别及工程作用；
2. 概括代表性进展；
3. 比较假设和证据；
4. 提炼有依据的未解决需求，或将已建立的能力带入下一主题；
5. 转向下一类别或最终定位。

不要每段都使用同一种 `However` 句式。最后一节收束到 gap，不重复整个引言。

## 十一、预期产物

完整定位任务可输出 **Problem-Positioning Brief**，按需包含下列内容；窄范围术语或引用核查只交付局部结论与已核实依据，不强制完整简报：

- 检索范围与四层语料；
- 与问题规模匹配的核心已验证文献，不为凑数扩充；
- 主题矩阵；
- 领域术语表；
- 一个精确、可验证的 gap；
- Related Work 结构；
- `VERIFY` 引用缺口；
- 明确的适用边界。

## 十二、质量门

- 工程与控制文献不能缺位；
- gap 必须从文献假设和实际条件推导；
- 引用不得超出原文支持范围；
- 近期论文用于校准当前术语；
- 经典论文用于事实和方法来源；
- 不复制语料句子；
- 最终研究定位能通过恰当分析或实验检验。
