# 工程应用术语与语言润色

[English](../../skills/engineering-terminology-polishing/SKILL.md)

套件版本：`4.2.21`

## 一、任务目标

提升准确性、可读性和工程期刊语体，不改变科学内容。润色是受约束修改，不是凭感觉重写。

修改论证推进、前人工作比较、贡献定位或防御性语言时，读取共享的[工程论证与语言写作指南](../../references/argument-and-prose-craft.md)。其执行步骤和工程例子自足，不要求安装外部 Skill。

## 二、建立修改锁

修改前确认权威版本、允许改写范围、已确认术语/公式/引用/数值、图表位置与样式、目标期刊和作者偏好。

语言任务不得擅自改变公式、设置、结果、引用、浮动体、表格字体和图大小。

同时存在上传压缩包和在线协作文稿时，先比较当前内容，再确定修改底稿；文件名相同不代表版本相同。针对实际发表文字的检查应基于有效 LaTeX 正文和编译 PDF，不把注释及禁用分支列为正文问题。分别记录本地修订、作者确认、在线同步和在线编译验证状态。

## 三、建立术语表

| 概念 | 首选术语 | 避免/限制 | 原因 |
|---|---|---|---|

覆盖过程/设备、任务、变量、传感器、工序、采样率、工况、领域知识、模型对象、指标和案例名称。标题、摘要、图、公式、表和结论使用一致术语。

通用术语和慎用词使用共享的[工程应用术语库中文版](../../references/engineering-application-terminology-bank_CN.md)；单篇论文的专用术语表应放在对应论文项目中，不加入共享词库。

已有基础名称先选[对应查阅组](../../references/engineering-application-terminology-bank_CN.md#九已核验核心名称与未完成范围)，再读确切记录、范围与单独的中文译名依据。分组只是阅读导航，不是互斥的问题/方法类别；局部用词查询不必载入全部无关记录。

推荐通用机制、模块、方法或操作类别时，执行名称准入：至少两篇不同的相关已发表期刊论文在相同意义下使用，歧义较大时尽量三至五篇；完整名称不能仅凭基础词背书。中文另行上网查可靠来源，译法未核实时保留英文身份并解释操作。区分单篇专名、作者新提名称、普通功能描述和通用术语；通用证据未完成不意味着删除准确专名，更不能另造一个机制替代。

state/condition、variable/attribute、sample/record 和变量特征的争议按[场景决策](../../references/terminology-decisions_CN.md)处理。根目录的只读 `scripts/audit_terminology.py` 可列候选与高频搭配，但不判断语法、不展开任意 TeX 宏，也不能替代活动 PDF 核查。语料未出现不等于禁用，作者偏好不升级为通用规则。

工具处理普通段落内换行，并以`line`/`end_line`给出源起止行；排除的元数据与字面指令行作为保守搭配边界。因此跨这类语法未命中不证明渲染后的搭配不存在；脚本分词范围与术语语义审查分别判断。

全文术语审计时提取重复实义词与 2--4 词搭配，重点检查承担工程含义的项目。三次可作可调整的起点，不遗漏仅出现一次但影响科学含义的词。争议用法核对相近已发表语境，覆盖数只统计实际检索的文献；全文审计不局限于作者举例。单句修改则保持授权范围，只指出必要的全文一致性关联。标准数学算子、激活函数、普通张量操作、方法名和数据集标签若无一致性问题可排除。按语义重构，不机械全篇替换。

## 四、工程对象优先

- process variables 先于 channels；
- production stages 先于 branches；
- sampling cycles 先于 interval embeddings；
- process connections 先于 graph edges；
- operating conditions 先于 domains；
- inspection regions 先于 spatial tokens。

若变量对应输入 channel，只定义一次，之后 `channel` 仅描述模型操作。

### 工业数据描述

- 按实际对象命名：一个学习或评价实例用 `sample`，测量值或时间步用 `observation/measurement`，数据集合用 `dataset`，被测或被操纵的过程量用 `process variable`。说明一个样本对应产品、批次、窗口还是其他单位。
- 不为词汇变化而把这些对象改称 `record`、`snapshot`、`descriptor` 或 `attribute`。确实描述数据库/日志记录、已定义的瞬时状态、提取后的特征描述量或语义/图属性时，这些词可以使用。`Dataset size` 指数量，不是数据集本身。
- 在数据介绍处说明类别含义和样本数量。正文普通故障名称用小写，专名或官方标识除外。只在新句确有需要时重复类别名称；多缺陷并存时的标签优先级必须保留，但不必反复完整列举类别。
- 按解释和复现实验所需，介绍生产来源、获准披露的采集时段、样本/标签构造、数据划分和预处理。不把参考论文的数据事实移植到本研究。开发集与其中的训练/验证子集应明确区分。
- 未获披露许可的产品规格、钢种、配方和筛选细节不写入交付稿。若省略影响复现或适用范围，应在作者交接中说明需要获准公开的概括描述。既检查可见 PDF，也检查拟共享的源文件；原始内容仅保留在受保护的本地历史中，不随投稿包交付。
- 删除 `snapshot` 等词时不能连同实际模型输入的定义一起删去。向量型工业样本用于时间序列模型时，须写清真实输入构造与参数；不能将填充或变量排列描述为采集到的时间动态。

## 五、准确使用知识术语

- `domain knowledge`：工艺拓扑、设备关系、控制逻辑、生产路线或工程规则；
- `expert knowledge`：操作员、工程师或专家提供的信息；
- `prior knowledge`：学习前已知的信息；
- `prior`：仅在数学 prior、graph、mask、constraint 或 bias 被定义时作技术名词。

根据句子位置使用 `fusion guided by domain knowledge` 或 `domain-knowledge-guided fusion`，避免长串连字符。

## 六、校准证据用词

- `benchmark case study`：在明确的参考任务或数据集上评价；公开可得性和实验控制需分别核实；
- `real-world industrial case study`：生产来源证据；
- `actual production conditions`：已测试的运行环境；
- `practical relevance/engineering applicability`：真实工业案例可在其已评价范围内支持；
- `online operation/industrial deployment`：必须有在线或部署证据。

工程正文和表格优先 `comparison methods` 或 `comparative methods`。`baseline` 可用于特定参考配置。

## 七、按功能修改句子

逐句检查：承载什么事实/关系/操作/结果/含义，主语是否正确，动词是否精确，限定词是否匹配证据，堆叠名词是否需要展开，句长是否超过逻辑承载能力。

从句应帮助说明观点间的关系；独立主张、长枚举或层层嵌套的方法细节遮蔽关系时拆句，不设固定从句数或词数。

从已知信息推进到新信息：以已定义的工程对象或结果承接上文，再引入下一步操作或含义。主语靠近动词，代词指向明确。删除不增加事实、关系、证据或必要说明的句子。准确的 `combine`、`adapt`、`extend` 应保留，换成更有宣传感的词不能提高创新性。

篇幅是结果，不是目标。以工程含义清楚、逻辑衔接完整且无冗余为标准：必要信息不足时补充，重复时删减，不为显示修改量而刻意缩短或拉长成熟稿件。

## 八、按角色修改段落

段落只承担一个主要任务：开头提出观点或转折，中间给证据/比较/技术发展，结尾给含义/边界/过渡。

若段落真正作用是 motivation，不以 `Fig. X illustrates...` 生硬开头。避免连续使用 `However`、`Therefore` 和 `To address this issue`。

核对段间的实质联系：上一段的能力、条件或结果是否推出下一段的要求或推断。推理已完整时不必补一句总结。给作者看的段落功能诊断不能混入论文正文。

## 九、摘要润色

核对六项：工程背景与挑战、现有局限、提出方法、核心设计、评价案例和证据结论。

第一句连接背景与困难但不能过载。删除不提供科学关系的实现式过渡。最后一句简洁说明实际评价及其支持的结论；benchmark/real-world 双案例只在确有这两类证据时使用，不写成排行榜，也不补造案例。

## 十、引言与 Related Work

- 开头后仍保持工业对象；
- 先定义过程/数据属性，再引入计算策略；
- 主题句承担段落论点；
- 公平介绍已有能力和相关假设；只有来源或有记录的比较支持时，才提出尚待满足的要求；
- gap 清楚后再引出方法；
- 贡献具体可检验。

根据真实创新路径组织论证：新问题/新表述、熟悉条件之间的耦合、既有问题上的新机制、工程适配，或有明确比较对象的实证发现。几类路径可以并存。不能在润色中虚构新问题，也不能因领域已有相关任务就削弱有证据的新表述。解释实质变化，并说明证据如何检验它。

Related Work 按能力发展和假设变化递进。区分显式假设、尚未测试的情境和已观察到的失败；未评价不等于不能解决。避免 `existing methods ignore industrial complexity` 等笼统贬低。把有依据的剩余要求接到机制和实验，贡献项数由真实进展决定，不预设数量。

## 十一、方法与实验语言

方法按：`动机 -> 输入输出 -> 操作 -> 工程含义 -> 过渡`。

结果按：`问题 -> 证据 -> 比较 -> 工程解释 -> 边界`。

不要只写 `Table X shows`，也不要把所有提升解释为 `better feature extraction`。

区分实测发现、机制解释和待检验假设。声称泛化时指出跨越了哪些工况或站点；声称实用价值时指出测得的工程收益。聚焦某类比较方法的结论只覆盖相应比较集，不需要宣称全面优于所有方法。图注与正文保持一致，不要求把同一结论机械重复三遍。

## 十二、减少模板化 AI 表达

删除或改写：

- 抽象名词和夸张形容词堆叠；
- 句长完全一致；
- 冗长铺垫；
- 无实质信息的 `plays a crucial role`、`has attracted extensive attention`；
- 重复防御性限定；
- 过多 `not only ... but also ...`；
- 无证据的 `novel`、`comprehensive`、`holistic`、`superior`。

目标是准确、自然并与作者风格兼容，不是规避检测器。

依据具体信息、逻辑和证据判断修改。词汇、标点和句长不能证明 AI 来源。采用语境诊断，不设机械禁词、标点或句长配额，也不以 AI 检测概率作为写作目标。

先把可疑句分为无信息元话语、必要范围条件、真实限制、有证据的限定或有用的概念对照。删除围绕假想异议展开的防御性叙述，以及无依据的“进一步阐明了方法优越性”等句子，直接说明对象、操作或发现。检查习惯性 `not X but Y`，同时保留科学上必要的区分。

若删去某个限定会改变主张含义，就将它保留在主张附近，摘要也适用。方法性限制的细节放 Methods，其含义放 Discussion。除另一个主张独立需要该边界才准确外，避免重复 caveat。保留真实不确定性并指出来源。普通实验不用 `protocol` 包装直接可说明的设置。

## 十三、语料与作者风格优先级

1. 科学和领域术语；
2. 目标期刊惯例；
3. 作者既有风格；
4. 通用科研写作偏好。

使用多篇近期目标期刊论文校准术语。作者既有论文只能在其技术术语通过外部语料核验后用于校准个人文风，不能为修改其自身术语提供规范依据。提取偏好但不复制句子。

## 十四、输出模式

- **直接修改**：编辑权威源、保持锁、按需编译；
- **建议改写**：作者决定前提供原文/修改稿；
- **术语审计**：列出不一致、计算机化、歧义或过度主张的术语。

- **正文与作者说明**：将拟入稿文字与作者诊断、未核实文献论断、待补证据和科学决策分开。先保留有依据的文字，再列明缺少的来源或实验。内部草稿中的占位符须清晰标记，不能用似乎合理的数值补齐，也不能把计划实验写成已完成结果。共享指南的例子均为假设场景，核实其事实前提后才可作为入稿文字。

## 十五、质量门

除明确纠错外含义和数值不变；工程与模型对象不混淆；术语一致；结论匹配证据；创新路径符合真实工作且前人能力得到公平描述；句子节奏自然；段落衔接反映逻辑；引用仍支持原论断；作者诊断和未解决占位符与可入稿正文明确分开；排版锁未被破坏。
