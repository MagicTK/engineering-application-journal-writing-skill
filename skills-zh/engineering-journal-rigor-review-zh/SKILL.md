# 工程应用顶刊严谨性审稿

[English](../../skills/engineering-journal-rigor-review/SKILL.md)

套件版本：`4.2.21`

## 一、任务目标

以工程应用期刊审稿人视角检查稿件，不只做语言或 ML leaderboard 审查。问题优先，区分稿件错误、证据不足、缺失实验、作者决策和可选建议。

## 二、确定审稿范围

记录：目标期刊、论文范式、工程任务、声称贡献、权威源/PDF、已知未完成项，以及内容/数据/排版锁。联合阅读最新正文、图表、参考文献和实验记录。

## 三、九个审稿维度

在查看主要结果前，先写一个简短审稿合同：记录稿件最强主张、支撑它所需的最低证据，以及哪些情况会迫使该主张降级。这样可减少看到结果后再反向调整标准。

1. **工程意义**：实际问题是否重要且定义清楚？
2. **定位与创新**：gap 是否有文献依据且非平凡？
3. **论证连贯**：问题、设计、主张、证据是否一致？
4. **方法正确性**：假设、公式、符号、维度和操作是否自洽？
5. **证据相关性**：实验是否真正检验对应主张？
6. **实验严谨性**：划分、对比、指标、消融和设置是否公平可重复？
7. **范围校准**：鲁棒、泛化、解释和工程结论是否有边界？
8. **来源与数据完整性**：引用、结果、图题、表格和正文是否一致？
9. **表达与排版**：术语、图表和页面是否专业可读？

## 四、严重程度

- **Critical**：使核心主张、任务、结果或投稿文件无效；
- **Major**：明显削弱创新、正确性、证据或可重复性；
- **Minor**：应修复但不改变核心结论；
- **Suggestion**：有清晰收益的可选改进。

不得把个人风格偏好夸大成 Major。

## 五、工程意义与定位

检查工业对象、决策目标、困难条件、方法回应和输出角色。背景驱动论文需证明工艺机制实际塑造方法；通用方法的问题应超出一个数据集但不能普适化。

核对工程与方法文献、最接近工作、假设差异、非稻草人批评、创新类型和贡献-实验映射。仅重命名已有模块不能构成创新。

### 跨论文贡献审查

对关联研究核对复用的数据/模块/代码与引用、实际机制变化、适用条件、新能力和隔离验证，使用[跨论文差异表](../../assets/templates/cross-paper-delta.md)。同一任务不否定独立后续工作，聚焦工程适配可以成立；反之仅换名称、种子、任意子集比例或措辞不能支撑独立论文。无实质增量时建议合并或放弃独立贡献，查重软件不能替代科学内容审查。A/B/C不决定期刊档次，也不降低证据要求。详见[贡献边界](../../references/research-planning-and-contribution.md)。

## 六、论证链

建立：

`观察 -> gap -> 需求 -> 设计 -> 主张 -> 证据 -> 结论`

标记：未解决的 motivation、未说明如何服务需求的模块、缺少对应证据的贡献（可能需要理论分析、实验或运行验证）、无关实验、结论新增主张，以及把 benchmark 与真实案例写成可互换数据集。

## 七、方法与数学

检查：

- 推理时可用信息；
- 集合、划分、mask、graph、方向和约束；
- 符号唯一性与维度；
- 概率与标签；
- 工序/采样率/聚类/类别索引；
- 损失项与权重；
- 公式、图、图题和正文的一致性；
- 公式是否提供必要形式化；
- 领域知识来源与进入模型的位置。

文字更清楚时，不要求增加公式。对核心数学主张先做最小例子核验：有限 logit 置零不使 softmax 后的类别概率为零；行归一化与列归一化的分母不同；块对角算子不证明物理独立。核对形状、求和轴、后续运算及可用实现；缺少代码意味着核验受限，不授权擅自修正方法。已发表参考文献可以提示核查位置，但不能取代数学判断。

## 八、实验与证据

逐主张检查：

- 数据来源和划分单位；
- 相邻窗口、重复产品、未来标签和归一化泄漏；
- 对比相关性与信息访问；
- 输入适配和设置可重复性；
- 主对比与消融对应；
- 真实可行的鲁棒性条件；
- 核心参数敏感性；
- 不平衡和 class-wise 诊断指标；
- 小幅差异的不确定性；
- 可视化是否有验证途径。

## 九、数值与跨载体一致性

尽可能计算或核对：样本总数、划分、weighted average、主表/消融 full model、摘要/引言/结论、图标签、百分比与百分点、指标名、方法名和引用键。

把问题分类为录入错误、算术错误、版本不一致、缺失结果或科学矛盾。

## 十、主张强度

| 主张 | 最低证据 |
|---|---|
| improvement | 公平对比 |
| component contribution | 合理的隔离对比、干预或分析 |
| robustness | 覆盖所声称扰动/工况范围的评价 |
| generalization | 对所声称总体或迁移设置的独立留出证据 |
| interpretability | 工艺、标签、扰动或专家验证 |
| efficiency | 参数/FLOPs/时间/内存 |
| engineering relevance | 与任务和工程条件对应的证据，不自动等于现场验证 |
| production applicability | 来自所声称产线场景的证据，明确采集和筛选范围 |
| deployment | 实际运行接入评价，并明确建议/影子/闭环范围 |

不能补证据时降低表述强度。判断 best、all classes、consistently 前先核对比较对象、指标及汇总层级；总体领先不等于逐类均最优。参见[一致性台账](../../references/experiment-evidence-design.md#9-consistency-ledger)。

## 十一、术语与排版

检查工程对象是否先于模型对象、变量/channel、domain/expert/prior knowledge、real-world/online/deployment、缩写、段落功能、图题独立性、表格字号和作者排版锁，以及 PDF 中的空栏、孤立文字、过小标签和浮动顺序。

## 十二、独立审稿轮次

条件允许时分开执行：工程领域、方法数学、实验数据、术语写作和对抗性最强主张检查。各轮先独立形成意见，再合并重复项，避免相互复述。

收到意见后的逐条回复与修改核对使用[审稿回复](../engineering-review-response-zh/SKILL.md)。研究证据迭代交接使用[协作流程](../../references/research-collaboration-workflow.md)。

## 十三、审稿输出

按 Critical、Major、Minor、Suggestion 排列。每项包括 ID、位置、观察、重要性、准确修复方式和判断依据。

随后给出：

- 应保留的优点；
- ready/minor revision/major revision/blocked 结论；
- 可直接修复项；
- 作者决策项；
- 实验负责人项，只保留真实冲突或缺失证据。

## 十四、修改后验证

逐项复核 Critical/Major，检查修复是否引入数值和排版问题，重新编译并查看受影响页面，最后检查引用。状态分为 resolved、partially resolved、accepted limitation 和 unresolved。

## 十五、投稿质量门

只有当核心主张均有证据、方法语义和数学自洽、划分与对比可辩护、数值跨载体一致、引用真实、工程意义清晰、结论不越界、最新源可编译且页面专业、剩余任务短而具体时，才可判断投稿准备完成。
